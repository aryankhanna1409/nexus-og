# Aegis-Net Engineering Instructions

## Primary specification

Read PROJECT_SPEC.md before implementing features. It is the
authoritative functional specification.

## Development workflow

- Implement incrementally by milestone.
- Do not build the entire system in one uncontrolled pass.
- Maintain IMPLEMENTATION_PLAN.md and ARCHITECTURE.md.
- Keep interfaces between components explicit.
- Prefer complete, tested vertical slices over disconnected mockups.
- Update documentation when behavior or interfaces change.

## Quality requirements

- Compile the C library with strict compiler warnings.
- Test memory handling, malformed inputs, and error paths.
- Use type hints and structured validation in Python.
- Write unit and integration tests.
- Run available tests after each meaningful change.
- Report actual test outcomes, including failures.
- Never claim an unexecuted test passed.

## AI and security requirements

- Distinguish facts, hypotheses, and recommendations.
- Use synthetic demonstration data by default.
- Keep API keys out of source control.
- Never execute arbitrary commands generated by an LLM.
- Use explicitly allowlisted tools for agent actions.
- Require approval for risky or destructive operations.
- Record agent actions in an auditable format.

## Scope control

Do not introduce unrelated technologies or dependencies without
justification. Do not leave core functionality as placeholders.
Identify incomplete work honestly.

## Final verification

Validate builds, tests, API integration, Docker startup, and the
end-to-end demo before declaring the application complete.
